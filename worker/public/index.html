A gateway for your TCP tools.

Connect a local client to a remote service through Tailcat and Cloudflare Workers. HTTP, databases, SSH, or your own protocol.

You provide the Tailcat address. Your client handles the application and its credentials. No website account needed.

Try a connection

Node.js 22.15+

This example connects curl to an HTTP service on the remote machine’s port 80.

  1. Expose the remote service

    On the machine running your HTTP service, install Tailcat and run:

    tailcat serve 80

    Keep it running. Use its Tailcat address in the next step.

  2. Start the local adapter

    Download both files into the same folder, then start forwarding:

    curl -fsSO https://tailcat-ssh-worker.iamwrm.workers.dev/transport.mjs
curl -fsSO https://tailcat-ssh-worker.iamwrm.workers.dev/transport-client.mjs
export TAILCAT_ADDR='tc…'
node transport.mjs forward --listen 127.0.0.1:8080 --port 80

  3. Use your usual client

    In another local terminal:

    curl http://127.0.0.1:8080/

    For another TCP service, change the exposed and destination ports, then use its client.

Choose your client

HTTP & databases
Forward a local port and connect with curl, a database client, or another TCP tool.
SSH & file transfers
Use native SSH or the Node client for commands, interactive shells, and SFTP copies. The Node client also works with rsync; rsync must be installed at both ends. SSH keys stay local.
Your own application
Build on the TCP SDK or implement the WebSocket protocol. Add or change client tools without redeploying the gateway.

An experimental gateway for light use. Each WebSocket carries one TCP connection. The current Free plan can interrupt long or large transfers. Use SSH or TLS when you need encryption between your client and the service.
